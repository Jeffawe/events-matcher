Events matcher

Match messy bank payments to the shared-expense invoices they pay. Names are abbreviated, one payment covers several people, bank alerts repeat, memos are free text. Anything the matcher can't be sure of is held for a person instead of guessed.

This page runs the project's real Python code in your browser (via Pyodide). Nothing you load is uploaded. It uses the rule-based matcher; the optional local language model needs the command-line version. Source and docs on GitHub.

Try it

Select all your event files and payments.json together (optionally expected.json to see a score).

Result

What happens

  1. Each payment's sender is matched to a person: exact name, then variants (initials, typos, nicknames, swapped order), scored as probabilities. Ambiguous senders are left for review.
  2. A memo like "covering Amara's share" or "cab 92 + cabin 360" is checked against the invoices with exact arithmetic.
  3. Money is applied to that person's invoices, never beyond what they owe. Each link carries two confidences: whose obligation it settles, and which invoice.
  4. Everything uncertain is listed as "Needs a person". The command-line tool has a review loop that remembers your decisions.
